# InkBridge

아이패드와 애플펜슬로 **노트북 화면 위에 직접 필기**하는 도구입니다.

노트북 화면이 아이패드에 그대로 보이고, 펜슬로 그으면 노트북 화면에도 같은 선이
나타납니다. 강의 중 슬라이드나 코드 위에 밑줄·동그라미를 치는 용도입니다.

**아이패드에는 아무것도 설치하지 않습니다.** Safari로 주소만 열면 됩니다.
앱스토어, Xcode, 개발자 계정 전부 필요 없습니다. 애플펜슬의 필압·기울기·팜리젝션은
Safari가 기본으로 지원하는 Pointer Events로 그대로 동작합니다.

---

## 준비물

- Windows 10 (2004 이상) 또는 Windows 11 노트북
- Python 3.10 이상 ([python.org](https://www.python.org/downloads/), 설치 시 **Add to PATH** 체크)
- 아이패드 + 애플펜슬
- 연결 수단: 셀룰러 모델이면 USB 케이블, Wi-Fi 전용 모델이면 노트북 모바일 핫스팟
  (아래 "아이패드 연결" 참고)

---

## 실행

저장소를 받은 뒤 `run.bat`을 더블클릭하면 끝입니다. 처음 한 번만 가상환경을 만들고
의존성을 설치하며, 이후에는 바로 실행됩니다.

```
run.bat
```

직접 실행하려면:

```bat
py -3 -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m inkbridge
```

실행하면 터미널에 아이패드에서 열 주소가 표시됩니다.

```
  On the iPad, open Safari and go to:

      http://172.20.10.2:8000  (USB tether)
      http://192.168.0.14:8000
```

> 첫 실행 때 Windows 방화벽 경고가 뜹니다. **개인 네트워크 허용**을 눌러야 아이패드가
> 접속할 수 있습니다. 실수로 차단했다면 `Windows 보안 → 방화벽 → 앱 허용`에서
> Python을 찾아 다시 허용하세요.

## 아이패드 연결

먼저 아이패드 모델을 확인하세요. `설정`에 **셀룰러** 항목이 있으면 셀룰러 모델,
없으면 Wi-Fi 전용 모델입니다. 여기서 가능한 연결 방식이 갈립니다.

### A. USB 케이블 — 셀룰러 모델만 가능

개인용 핫스팟은 셀룰러 모뎀을 공유하는 기능이라 **Wi-Fi 전용 아이패드에는 설정에
항목 자체가 없습니다.** 셀룰러 모델이라면 이 방식이 지연이 가장 낮습니다.
(요금제가 없어도 됩니다. USB 구간만 쓰고 셀룰러 데이터는 소모하지 않습니다.)

1. 노트북에 [Apple Devices](https://apps.microsoft.com/detail/9np83lwlpz9k) 앱을
   설치합니다. USB 드라이버 때문에 필요하며, 실행해 둘 필요는 없습니다.
2. 아이패드를 USB로 연결하고, 아이패드에서 **이 컴퓨터를 신뢰** 를 누릅니다.
3. 아이패드에서 `설정 → 개인용 핫스팟 → 다른 사람의 연결 허용`을 켭니다.
4. 노트북이 `172.20.10.x` 주소를 받습니다. 터미널에 `(USB tether)`로 표시된 주소를
   아이패드 Safari에 입력합니다.

### B. 노트북 모바일 핫스팟 — Wi-Fi 전용 모델에 권장

Wi-Fi 전용 아이패드에서 가장 실용적인 방법입니다. 노트북이 직접 Wi-Fi를 쏘기 때문에
**강의실 공유기나 인터넷이 아예 없어도** 되고, 공용 Wi-Fi의 기기 간 통신 차단
문제도 없습니다. 무선이지만 노트북↔아이패드 직결이라 지연도 충분히 낮습니다.

1. 노트북에서 `설정 → 네트워크 및 인터넷 → 모바일 핫스팟`을 켭니다.
2. 표시된 네트워크 이름과 암호로 아이패드를 접속시킵니다.
3. 터미널에 표시된 `192.168.137.x` 주소를 아이패드 Safari에 입력합니다.

### C. 같은 Wi-Fi

노트북과 아이패드를 같은 공유기에 두고, 터미널에 표시된 주소 중 하나를 엽니다.
가장 간단하지만, 회사나 학교의 공용 Wi-Fi는 기기 간 통신(AP isolation)을 막는
경우가 많아 접속이 안 될 수 있습니다. 그럴 때는 B를 쓰세요.

### D. 진짜 유선이 꼭 필요하다면 — USB-C 아이패드

USB-C 아이패드(iPad Pro/Air M 시리즈, iPad 10세대 이후)는 USB-C 이더넷 어댑터를
지원합니다. 아이패드 → 이더넷 어댑터 → 랜선 → 노트북 이더넷 포트로 직결하면
셀룰러 모델이 아니어도 완전한 유선 연결이 됩니다. 양쪽 모두 링크로컬 주소
(`169.254.x.x`)를 자동으로 잡습니다. 어댑터가 필요하고 설정이 번거로워서,
대부분의 경우 B가 더 낫습니다.

### 전체화면으로 쓰기

Safari에서 **공유 → 홈 화면에 추가** 를 한 번 해두면, 이후 홈 화면 아이콘으로 열 때
Safari 주소창 없이 전체화면으로 뜹니다. 강의 중에는 이쪽이 훨씬 낫습니다.

## 온라인 강의라면 `--share-ink`

여기가 중요합니다. 필기를 화면 위에 그리는 방식이 두 가지고, 상황에 따라 골라야 합니다.

**대면 강의 (프로젝터·HDMI) — 기본값 그대로**

```
run.bat
```

필기는 노트북 화면에 보이고 프로젝터에도 그대로 나갑니다. 대신 화면 캡처에서는
제외되므로, 아이패드로 되돌아오는 미러 영상에 필기가 중복으로 찍히지 않습니다.

**온라인 강의 (Zoom·Teams 화면 공유) — `--share-ink` 필요**

```
run.bat --share-ink
```

기본값 그대로 두면 Zoom 화면 공유에 **필기가 보이지 않습니다.** 원격 수강생에게
마킹을 보여주려면 반드시 이 옵션을 켜세요. 이때는 우리 미러도 필기를 같이 캡처해서
아이패드로 되돌려 보내지만, 좌표가 정확히 겹치므로 화면상 차이는 거의 없습니다.

## 옵션

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--share-ink` | 꺼짐 | 위 설명 참고. 온라인 강의면 켜세요 |
| `--monitor N` | `1` | 미러링할 모니터. `1`이 주 모니터입니다 |
| `--width N` | `1280` | 전송 해상도. 낮출수록 빨라집니다 (`960` 권장: 체감 지연이 눈에 띄게 줄어듭니다) |
| `--fps N` | `30` | 초당 캡처 상한 |
| `--quality N` | `55` | JPEG 품질. 부하가 걸리면 자동으로 낮아집니다 |
| `--port N` | `8000` | 포트 |

예: 사양이 낮은 노트북에서 반응을 최대한 빠르게

```
run.bat --width 960 --fps 24
```

## 동작 원리

```
   iPad (Safari)                             Windows 노트북
  ┌──────────────┐                          ┌──────────────────┐
  │  화면 캔버스  │ ◀──── JPEG 프레임 ────── │  화면 캡처        │
  │  잉크 캔버스  │        /ws/screen        │  (변경 시에만)    │
  │              │ ─────── ack ──────────▶  │                  │
  │              │                          │                  │
  │  펜슬 입력    │ ─────── 좌표 ─────────▶  │  투명 오버레이    │
  └──────────────┘        /ws/pen           └──────────────────┘
```

설계에서 신경 쓴 지점 세 가지입니다.

**1. 소켓을 둘로 나눴습니다.** 화면 프레임과 펜 입력이 같은 소켓을 쓰면, 전송 중인
60KB짜리 JPEG 뒤에 펜 좌표가 줄을 서게 됩니다(head-of-line blocking). 채널을 분리해서
필기 입력이 영상 때문에 밀리지 않도록 했습니다.

**2. 프레임은 ack를 받아야 다음 걸 보냅니다.** 이게 없으면 소켓 버퍼가 무한 큐가 되어,
몇 분 지나면 미러가 실제 화면보다 몇 초씩 뒤처집니다. 아이패드가 "그렸다"고 알려온
뒤에만 다음 프레임을 보내고, 기다리는 동안 쌓인 프레임은 **가장 최신 것만 남기고
버립니다.** 오래된 프레임을 전송하는 건 대역폭 낭비이자 지연 그 자체입니다.

**3. 필기는 네트워크를 기다리지 않습니다.** 펜슬 좌표는 아이패드 화면에 즉시 그려지고,
같은 좌표가 노트북으로 따로 전송됩니다. 네트워크가 잠깐 끊겨도 그리는 느낌 자체는
망가지지 않습니다. 또 Safari의 `pointermove`는 펜슬의 실제 샘플링 속도보다 느리게
전달되기 때문에, `getCoalescedEvents()`로 누락된 중간 샘플까지 모아 씁니다. 이걸
안 하면 빠르게 그은 곡선이 각진 다각선으로 보입니다.

**정지 화면에서는 거의 아무것도 하지 않습니다.** 캡처한 원본을 이전 프레임과 먼저
비교해서, 같으면 축소·인코딩을 아예 건너뜁니다. 측정해 보니 슬라이드가 멈춰 있을 때
CPU 사용량이 코어의 약 84%에서 0.4%로 떨어집니다. 강의 내내 팬이 도는 것과 아닌 것의
차이입니다.

## 문제 해결

**아이패드에서 주소가 안 열립니다**
대부분 방화벽입니다. 위 "실행" 항목의 방화벽 안내를 먼저 확인하세요.
그래도 안 되면 공용 Wi-Fi가 기기 간 통신을 막고 있을 가능성이 큽니다.
연결 방식 B(노트북 모바일 핫스팟)로 바꾸면 대부분 해결됩니다.

**아이패드 설정에 `개인용 핫스팟`이 없습니다**
Wi-Fi 전용 모델입니다. 정상이며, 이 모델은 USB 테더링을 쓸 수 없습니다.
연결 방식 B를 쓰세요.

**필기가 펜슬 위치와 어긋납니다**
배율이 조정된 디스플레이에서 생길 수 있습니다. 프로그램이 DPI 인식을 켜서 처리하지만,
그래도 어긋나면 노트북을 껐다 켠 뒤 다시 실행해 보세요. 여러 모니터를 쓴다면
`--monitor` 번호가 맞는지 확인하세요.

**노트북 화면 클릭이 안 됩니다**
오버레이는 클릭이 통과하도록 만들어져 있습니다. 만약 막힌다면 창이 제대로 만들어지지
않은 것이니 `--verbose`로 실행해 로그를 확인하세요.

**Zoom 공유에 필기가 안 보입니다**
`--share-ink` 옵션을 켜세요. 위 설명 참고.

**선이 각지게 보이거나 끊깁니다**
`--width 960`으로 낮춰 보세요. 대역폭이 부족하면 프레임보다 입력이 먼저 밀립니다.

## 테스트

```
pip install pytest pytest-asyncio
python -m pytest tests/ -q
```

19개 테스트가 스트로크 모델과 WebSocket 프로토콜을 검증합니다. 특히 지연의 핵심인
ack 페이싱(밀린 프레임을 버리고 최신 것만 보내는지), ack가 유실됐을 때 미러가
영구히 멈추지 않는지, 깨진 입력이 서버를 죽이지 않는지를 확인합니다.
Qt와 화면 캡처는 스텁으로 대체해서 화면 없는 환경에서도 실행됩니다.

## 아직 확인하지 못한 것

정직하게 밝힙니다. 이 코드는 Linux 컨테이너에서 작성했고, **실제 Windows 노트북과
아이패드 조합으로는 실행해 보지 못했습니다.** 검증한 것과 못 한 것은 다음과 같습니다.

검증함
- 스트로크 모델, WebSocket 프로토콜, ack 페이싱 (자동 테스트 19개 통과)
- BGRA→RGB 변환의 정확성, 인코딩 처리량 (실측 36fps 상한, 프레임당 62KB)
- 정지 화면 조기 종료의 효과 (실측 CPU 84% → 0.4%)

확인 필요 — 실제 환경에서 처음 돌려볼 때 봐주세요
- 투명 오버레이의 클릭 통과와 포커스 미탈취 동작 (Win32 `WS_EX_TRANSPARENT`)
- 캡처 제외 동작 (`SetWindowDisplayAffinity`). Windows 10 2004 미만에서는 무시되며,
  그 경우 필기가 미러에 중복으로 찍힐 수 있습니다. 겹쳐 보이면 `--share-ink`를 켜서
  동작을 통일하는 편이 깔끔합니다
- 배율 조정 디스플레이에서의 좌표 정확도
- 실제 펜슬 필압 곡선의 체감

잘 안 되는 부분이 있으면 어떤 증상인지 알려주시면 바로 잡겠습니다.
